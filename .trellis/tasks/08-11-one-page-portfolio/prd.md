# 一页式求职网站改造

## Goal

把现有偏开发者终端风的个人站，改造成面向 AI 产品经理校招 / 实习的一页式个人作品集。招聘方应能在一次连续浏览中快速理解 Zoo 的定位、经历、项目、能力与联系方式，同时感受到鲜明、好玩且克制的产品感。

## Confirmed Facts

- 当前首页已是单页落地站，但内容仍以 `AI PM & Vibe Coder`、终端启动动画、技术标签和项目卡片为主；顶部已有锚点导航，active 状态目前依赖 URL hash，而不是滚动位置。
- Ask Zoo 当前是独立 `/ask-zoo` 页面，已支持流式回复、会话存储与 `?q=` 自动提问；新方案要把入口和对话窗口融入首页，但保留现有服务端聊天能力。
- 参考 `ddaniel.dev` 的一页式履历顺序与 contact 双栏表单；不延续它的纯开发者终端视觉。
- 参考 `doisena.jp` 的大胆字号、黑色描边、作品主导布局、横向切换和全屏弹层所形成的趣味与品牌感；不照搬插画师内容模型。
- 项目使用 Next.js 16.2.3；开发前必须读取仓库内对应 Next.js 文档。
- 当前 `main` 工作树在任务创建前 clean，且比 `origin/main` ahead 3；本任务属于大功能，实施阶段应在 feature 分支完成，未经用户测试确认不合并。

## Requirements

### Information Architecture

- 整站为单一路由的连续纵向页面；主要内容段落各自形成接近独立一屏的章节，而不是独立 route。
- 顶部 sticky 导航左侧显示姓名，右侧显示章节目录；点击平滑跳转，滚动时自动选中当前章节。
- 章节顺序为：首页 / Work / Projects / Skills / Contact / Ask / Footer。

### Hero

- 左侧包含姓名、求职意向、简短自我介绍、学历与专业。
- 右侧使用轻量 SVG 或交互视觉表达产品经理身份；炫技必须服务于个人定位，不使用无意义粒子或通用科技装饰。

### Work

- 使用由近及远的纵向时间线，中轴线与节点表达时间顺序。
- 默认显示公司名、岗位、时间段；hover 或 focus 后展开职责与成果详情。
- 第一版允许 mock 文案，结构需便于随后替换为真实简历内容。

### Projects

- 当前仅两个重点项目，每个项目占据一屏式叙事段落。
- 向下滚动时，上一个项目收束并自然过渡到下一个项目；避免为了项目数量少而制造空洞的项目索引页。
- 左侧展示标题、产品信息、工作内容、官网/GitHub/时间等元信息；右侧展示项目截图。

### Skills

- 作为独立章节，以能力与应用场景为第一层、工具与相关项目证据为第二层，形成能力 × 工具矩阵。
- 不使用自评百分比、星级或无语境 Logo 墙。

### Contact

- 左侧展示头像及 GitHub、邮箱、电话、微信。
- 右侧提供可直接发送邮件的表单，并显示提交中、成功、校验失败、限流与服务失败状态。
- 表单通过 Next.js Route Handler 调用 Resend；服务端固定发件人，访客邮箱仅作为 `replyTo`。
- 首版使用 honeypot、字段长度 / 格式校验和独立限流，不引入依赖 Cloudflare 前端脚本的验证码，以保证国内访问可用性。
- 成功状态只承诺“发送请求已提交”，不谎称邮件已送达收件箱。

### Footer

- 左侧以大字号显示姓名，底部包含 Back to top。
- Footer 不是普通版权条，而是完整的收束章节。

### Ask Zoo

- 页面右下角常驻头像入口，hover/focus 显示 `Ask me more` 提示；首页末尾提供独立一屏 Ask 章节。
- 点击后在当前页面打开对话窗口/弹层，而不是导航到新页面。
- 滚动至 Ask 章节后，浮动入口在视觉上融入该章节的 AI persona 舞台，形成连续的 dock / transition；离开章节后恢复右下浮动。
- 保留键盘可达性、关闭方式、移动端适配和 reduced-motion 降级。
- 首页使用原生 `<dialog>` 承载窗口，旧 `/ask-zoo` 保留为独立 fallback；两者复用同一聊天组件与状态逻辑。
- 抽取聊天逻辑时修复 SSE 跨网络 chunk 残片未缓冲导致的偶发丢字风险。

### Visual and Interaction Direction

- 目标是“有意思、有产品感的产品经理个人网站”，不是纯技术人员作品集，也不是通用简历模板。
- 核心印象确定为“有判断力的产品创造者”：先让人感到思路清晰、能做取舍，再通过少数有趣体验证明创造力。
- 光标需要有设计，但不能妨碍文本选择、链接识别、表单输入或触屏体验。
- 动效集中在少数 signature moments（标志性时刻），其余区域保持清晰克制。
- Hero SVG、项目 scroll-linked 状态和 Ask Zoo 共享转场使用 Motion；章节 sticky 与目录 active 使用 CSS sticky / IntersectionObserver。不引入 GSAP 或 Lenis。

## Acceptance Criteria

- [ ] 访问首页可按既定顺序连续浏览六个章节，无需进入子页面理解核心求职信息。
- [ ] 桌面端点击目录可平滑跳转；滚动经过章节时，目录 active 状态自动且正确地更新。
- [ ] Hero 在首屏内清晰表达姓名、求职方向、简介和教育信息，并包含与产品定位相关的独特视觉。
- [ ] Work 时间线支持鼠标、键盘和触屏访问详情，不依赖 hover 才能获得核心信息。
- [ ] 两个 Project 均拥有完整的一屏式叙事，在主流桌面和移动屏幕上不会出现内容被 sticky/折叠效果遮挡。
- [ ] Contact 信息完整，邮件表单具备明确的提交中、成功与失败反馈。
- [ ] Ask Zoo 可在首页内打开、对话、关闭，并在独立 Ask 章节完成视觉归位；聊天能力不回退。
- [ ] 自定义光标在交互元素上有可辨识反馈，并在触屏与 reduced-motion 环境下安全降级。
- [ ] 页面在移动端可完整使用，键盘焦点清晰，核心内容不因动效或 JavaScript 失效而不可读。
- [ ] 最终视觉不再以终端/代码 UI 为主语言，招聘方能优先感知产品判断、项目叙事和个人个性。

## Out of Scope

- 本轮不确定真实简历文案；Work 可先使用 mock 内容。
- 不新增项目详情 route 或多页作品集结构。
- 不在规划确认前实现代码、重写 Ask Zoo 后端或合并到远端分支。

## Key Decisions

- 核心人格：有判断力的产品创造者；不把“懂技术”或“视觉风格强”作为第一记忆点。
- 视觉母体：互动作品年鉴。借用独立设计刊物的大字、粗分隔、满版图片和章节节奏，但用求职叙事与产品证据承载内容。
- 性格强度：冷静主版、局部出格。约 80% 内容保持清晰可信，把表现力集中在 Hero、项目换页、光标和 Ask Zoo。
- 光标：编辑校对笔隐喻。默认克制，经过可交互内容时以圈选、下划线和动作词提供反馈；表单、文本选择、触屏和 reduced-motion 使用安全降级。
- Hero signature visual：用动态 SVG 把散乱的需求碎片经过圈选、取舍和收束，变成清晰的可交付产品，表达“把模糊变成可交付”。
- 色彩基调：黑纸 + 米白 + 冰蓝。为避免回到开发者站气质，应移除终端语法、霓虹渐变和技术标签式装饰，用年鉴排版与图像主导视觉。
- 字体人格：巨型无衬线标题 + 人文无衬线正文；等宽字体仅用于时间、URL、状态等元信息。字体资源必须本地化。
- Work 详情：桌面 hover/focus 预览，click/Enter 锁定展开；移动端 tap 展开。核心摘要始终可见。
- Project 转场：每个项目占据 sticky 一屏，下一张年鉴页从底部覆盖上一张；移动端和 reduced-motion 降级为普通纵向项目页。
- Skills：采用能力 × 工具矩阵，但能力与应用场景是第一层，具体工具和相关项目证据是第二层；不使用自评百分比或无语境 Logo 墙。
- 求职目标：AI 产品经理校招 / 实习；内容优先证明成长潜力、学习速度、实习行动与两个 AI 产品项目中的判断，不使用虚构的社招资历感。
- Ask Zoo：定位为 Zoo 的 AI 分身，支持开放聊天并提供快捷提示词；默认围绕本人、经历、项目与产品观点，回答需受已提供材料约束，避免编造个人事实。
- 语言：中文承担核心叙事；英文仅用于 Work / Projects / Skills 等章节标签、编号和元信息，不做双语切换。

## Deferred Items

- 精确字体文件与许可、真实简历文案、项目截图、学校 / 专业、头像和联系方式在实施对应切片前补齐；首轮可使用明确标注的 mock 数据。
- Resend 发件域名、收件地址与环境变量需在 Contact 切片前由用户提供或确认。
- motion 参数在视觉实现阶段按 1366×768、移动端和 reduced-motion 三档验证后定稿。
