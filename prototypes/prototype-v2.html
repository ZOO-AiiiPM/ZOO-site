用 Claude Code 三天做了一个完整的 SaaS 产品

2026-04-08 ~2800 字 8 min read

上周我用 Claude Code 做了一个实验：能不能在三天内，从一个想法变成一个可用的 SaaS 产品？结果超出预期。

为什么做这个实验

作为一个 AI PM，我一直在思考：当 AI 能帮你写代码时，PM 的价值到底在哪？不是 Prompt 写得好不好，而是你能不能把一个模糊的想法变成一个结构清晰、逻辑自洽的产品。

Vibe Coding 不是让 AI 替你写代码，而是让你用产品思维和 AI 协作，把想法快速变成现实。

Day 1：需求定义与架构设计

第一天没写一行代码。全部时间花在需求文档和信息架构上。我用 CLAUDE.md 把项目背景、技术约束、设计规范全部写清楚。

Day 2：核心功能开发

有了清晰的需求文档，Claude Code 的表现非常稳定。关键心得：指令越具体，输出质量越高。这和写 PRD 是一回事。

// 不要这样：
"帮我做一个用户管理系统"

// 要这样：
"参照 CLAUDE.md 中的用户模型定义，
 实现 /api/users 的 CRUD 接口，
 使用 Supabase Auth，
 错误处理参考 lib/errors.ts"

几个反直觉的发现

1. 写需求文档的时间不能省——花在需求上的时间会在开发阶段 10 倍返还。

2. PM 的价值不降反升——当开发成本趋近于零，决定做什么比怎么做更重要。

3. 审美是新的技术壁垒——AI 能写代码但不能替你做审美判断。
